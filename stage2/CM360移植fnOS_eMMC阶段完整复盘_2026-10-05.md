## 三、eMMC 最终布局（MBR/DOS）

```
LBA 0            MBR（磁盘签名 0x12345678，p1 置 0x80 可引导位）
LBA 2048         兜底裸内核 Image-6.6.uimage（72742 扇区）★ 就是这个把 hwsetting 盖了
LBA 74880        兜底裸 DTB（15 扇区）
LBA 77824        p1  ext4  256 MiB  LABEL=BOOT   ← 内含 Image-6.6.uimage + rtd1296-cm360.dtb
LBA 602112       p2  btrfs 6.99 GiB LABEL=rootfs  ← 已收 `btrfs receive` 的根（subvol=/root，rw）
```
- p2 UUID `e943d468-6d97-4666-8e3c-bc52442bec60`（与 sda 的 `5a345cec…` 不同）
- p1 ext4 **特意关掉 `metadata_csum`/`64bit`**（u-boot 2015.07 不认）

## 四、★★ 事故复盘：为什么板子卡死在 FSBL

### 现象（可 100% 复现，与 ESC 洪流无关——用纯被动无洪流也复现了）
```
C1:80000000
C2
?
C3hswitch frequency to 0x00000046
frequency divider is 0x00000080
switch frequency to 0x00000046
frequency divider is 0x00000004
switch to SDR 8 bit
switch bus width to 0x00000008 bits success
0000001\xff        ← 正常时这里是 "hwsetting size: 00000BE4"
C1:80000000        ← 退回 C1/C2 重启
C2
?uu3-1             ← 死等；此后串口静默、无 IP
```

### 三条独立证据钉死根因
1. **原厂 eMMC GPT 分区 1 就叫 `"uboot"`**（LBA 0x8000-0xbfff，8 MiB，无文件系统）；
   u-boot 打印过 `Factory: pp:1, seq#:0x10f, size:0x20400` —— `pp:1` = 分区 1
2. **`dvrboot.exe.bin` 的 strings**（决定性）：
   ```
   hwsetting: block 0x
   read hwsetting back: block 0x
   verify hwsetting falied
   emmc: do_hide_hwsetting_e() read blk 0x     ← hwsetting 存在 eMMC 的"隐藏块"
   emmc: do_hide_hwsetting_e() write blk 0x
   hwsetting size:                              ← 与板子打印的字符串一字不差
   U-Boot 2015.07 (Apr 27 2018 - 09:10:25 -0700)
   ```
3. **时序对比**（干净日志 `stage0/shot_uboot_01.log`，未擦盘、无洪流）：
   | | 擦盘前（正常） | 擦盘后（失败） |
   |---|---|---|
   | `switch bus width…success` → hwsetting | **17 ms** 打出 `hwsetting size: 00000BE4` | **315 ms** 打出残缺值 |
   | 之后 | `C4` → `Goto FSBL: 0x10100000` → u-boot | 退回 `C1/C2` 死等 |

### 结论
**RTD1296 把 `hwsetting`（DRAM/eMMC 启动配置）放在 eMMC 低区的"隐藏块"里**（参考 SD 卡写法
`sd write 0x1500000 0x50 0x3f0`，u-boot 就在 LBA 0x50 = 40KB 起）。
**我们清零 eMMC 前 1 MiB、并从 LBA 2048 写 37MB 内核 —— 把它彻底盖掉了。**

> **教训：分区表之外 ≠ 空的。动闪存前必须先把前 16 MiB 整段 dump 留档。**
> 而且自造的"兜底数据"绝不能放进闪存低区。

## 五、恢复方案（官方文档路径，工具已备好但**还没执行**）

SoC 有 **ROM 级 Phoenix Monitor**，绕开 FSBL/u-boot：

| 步骤 | 动作 |
|---|---|
| 1 | **按住 `Ctrl+Q` 上电** → 出 `d/g/r>` 提示符 |
| 2 | `h` → YMODEM 发 `RTD1296_hwsetting_BOOT_4DDR4_4Gb_s1866_padding.bin` |
| 3 | `s` → 输入 `98007058`↵ `01500000`↵ |
| 4 | `d` → YMODEM 发 `dvrboot.exe.bin` |
| 5 | `g` → 开始烧写 |

**执行命令**（串口代理必须先停）：
```bash
cd ~/WorkBuddy/2026-10-03-23-33-10/rtd1296-fnnas/stage2
./agent-ctl.sh stop        # 独占 /dev/ttyUSB0
/usr/bin/python3 phoenix_recover.py \
  --hwsetting out/rec/RTD1296_hwsetting_BOOT_4DDR4_4Gb_s1866_padding.bin \
  --dvrboot   out/rec/dvrboot.exe.bin \
  --flood-secs 300 --flood-chunk 16 --flood-gap 4 \
  --log logs/phoenix-rawN.bin
# 然后给板子断电→等5秒→上电
./agent-ctl.sh start       # 恢复串口代理
```
- ★ 必须用 **`/usr/bin/python3`**（有 pyserial 3.5；`.workbuddy` 自带的 python 没有）
- ★ 单字母命令 `h/s/d/g` **不要回车**（按下即执行）；'C' 刷屏期间别乱按键（会软锁）
- ★ 洪流必须**持续稳流**（脚本已改为后台线程 16B/4ms ≈ 4000 B/s），"爆发+长静默"占空比仅 2% 会漏检
- ★ ⚠️ 已知坑：`pgrep -f phoenix_recover` 会匹配到**调用者自己的命令行**，`kill` 会把自己的 shell 杀掉 —— 用 `pgrep -f 'phoenix_[r]ecover'`

**未解的坑**：Phoenix Monitor 至今没进去过（洪流升级到持续稳流后仍未验证成功），
怀疑还需要**先停代理再由脚本独占串口**（第一次试时两个脚本实例抢同一个串口、且旧实例还占着口）。

**恢复后的影响**：u-boot 会换成 BPI-W2 的（2018-04-27），失去 Synology 的 `syno_*` env；
但 BPI-W2 u-boot 有文档化 `go ru` U盘安装模式、ESC 进 console、eMMC/SD 启动，**对移植 fnOS 更有利**。

## 六、踩过的坑速查（本轮新增）

1. **`sudo -S -p ''` 必须整体包进 `bash -c`**，否则 `;`/`&&` 逃出 sudo
2. **paramiko `exec_command(timeout=)` 默认 120s** 会掐断长任务；客户端断开但远端脚本
   stdout 已失效 → 下一个 `echo` 撞 EPIPE/SIGPIPE 死掉（set -e）→ 留下半成品。长任务用 `timeout=None`
3. **`brd.py pushcmd`（`sudo -S ... dd`）是错的**：sudo 从 stdin 读密码，stdin 却是二进制流。
   正确做法：先 `push` 到 `/tmp/xxx`，再 `sudo dd if=/tmp/xxx`
4. **`findmnt -S /dev/mmcblk0` 匹配不到分区挂载源**（精确相等匹配）→ 配 pipefail+set -e 会**静默退出**。
   改用 `findmnt -rno TARGET,SOURCE | awk '$2 ~ /^\/dev\/mmcblk0/'`
5. **`btrfs receive` 收到的子卷带 `received_uuid`，`property set ro false` 被拒**
   → 只读子卷当根会让整个 `/` 只读。解法：**对只读子卷打可写快照**
6. **`set-default` 到子卷后，`mount $DEV $M` 直接进子卷内部** → 要看顶层必须 `-o subvolid=5`
7. `btrfs subvolume list` 行里 `top level N path` **含空格**，路径是 `$NF`，别用 `read` 切字段
8. 默认子卷不能删（`WARNING: not deleting default subvolume`）→ 先 set-default 新的再删旧的
9. u-boot 2015.07 的 ext4 **不认 `metadata_csum`/`64bit`** → 引导分区要
   `mke2fs -O ^metadata_csum,^64bit,...`；给 ext4 镜像塞文件用 `debugfs -w -R "write ..."`（免 root）
10. **`btrfs send` 流出的是解压后数据**（5.0 GiB vs 实际占用 2.19 GiB）→ 目标分区必须 ≥5.4 GiB
11. `truncate -s` 把兜底裸镜像**补齐到扇区整数倍**，否则按扇区整段 md5 比不上
12. **u-boot 有 `source - run script from memory`** → 长命令全部塞进 TFTP 来的 `.scr`，
    串口只敲 3 条短命令，彻底绕开 32 字符限制
13. ★★ **绝对不要动闪存的低区**（hwsetting / 二级引导在那）
14. ★ `pgrep -f <脚本名>` 会匹配到调用者自己的命令行，`kill` 会杀掉自己的 shell。
    用 `pgrep -f 'name_[x]'` 这种不自匹配的写法
15. 诊断"启动到某处就死"：**先找同一台机器改动前的干净日志逐行对比**（这次靠 300ms vs 17ms
    的时序差把范围缩到 hwsetting）
